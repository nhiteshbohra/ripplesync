COMMAND: backfill (download history)
  Stage 1: Start-up   (files: __main__.py, cli.py, files.py, config.py, logsetup.py, runcontrol.py)
      __main__.py:(module level) --> cli.py:main()
          command-line words (sys.argv) in → exit code out
      cli.py:main() --> cli.py:build_parser()
          → argparse parser; gives the command name and its options
      cli.py:main() --> cli.py:_main()
          parsed options + the COMMANDS entry for the command
      cli.py:_main() --> files.py:load_env()
          process environment in → .env values added without overriding; EnvFile (which file, which keys came from it)
      cli.py:_main() --> files.py:base_dir()
          environment + EnvFile → base folder for relative paths (stop file, range file, logs, locks)
      cli.py:_main() --> config.py:Config.from_env()
          environment variables + base folder → Config (every setting checked at once; ConfigError → exit 2)
      cli.py:_main() --> logsetup.py:setup_logging()
          LOG_LEVEL, LOG_FILE, LOG_MAX_MB, LOG_BACKUPS → log handlers (screen + rotating file)
      cli.py:_main() --> runcontrol.py:install_stop_signal()
          installs SIGTERM / SIGBREAK handlers (Ctrl+C graceful for ingest commands)
      cli.py:_main() --> runcontrol.py:StopFlag.__init__()
          ingest commands only: PROCESS_STATUS_FILE + command name → stop check used by every loop
      cli.py:_main() --> cli.py:_acquire_lock()
          ingest commands only: base folder + command → lock held for the whole run (another copy → exit 5)
      cli.py:_acquire_lock() --> runcontrol.py:lock_path()
          base folder + command → <base>/xrpl_ingest.<command>.lock
  Stage 2: backfill · choose the range   (files: cli.py, files.py)
      cli.py:_main() --> cli.py:_cmd_backfill()
          Run (options, Config, stop check, store opener) → exit code
      cli.py:_cmd_backfill() --> files.py:choose_range()
          --start / --end and the range-file path → BackfillRange(start, end, where it came from)
      files.py:choose_range() --> files.py:load_range()
          range-file path → BackfillRange (defaults if the file is missing)
      files.py:load_range() --> files.py:parse_range()
          file text → start / end; errors name the file and line
  Stage 3: backfill · look at the node and plan chunks   (files: cli.py, backfill.py, store.py, source.py, ledger_ranges.py)
      cli.py:_cmd_backfill() --> backfill.py:run_backfill()
          Config, start, end, stop check → summary (chunks run, ledgers ok / failed, ranges the node lacks)
      backfill.py:run_backfill() --> store.py:MongoStore.from_config()
          Config (MONGO_URI, DB_NAME, collection names) → MongoStore
      backfill.py:run_backfill() --> store.py:MongoStore.ensure_indexes()
          creates the unique indexes (safe to repeat)
      backfill.py:run_backfill() --> source.py:WsSource.from_config()
          Config (SERVERS, timeouts, EXPECTED_NETWORK_ID) → WsSource
      backfill.py:run_backfill() --> backfill.py:discover_node()

      backfill.py:discover_node() --> source.py:WsSource.server_info()
          → server_info answer (complete_ledgers, validated_ledger)
      backfill.py:discover_node() --> ledger_ranges.py:parse_complete_ledgers()
          '32570-100,105' text → list of (start, end) ranges
      backfill.py:run_backfill() --> store.py:MongoStore.done_chunks()
          start, end → set of chunks already finished (this is how a restart resumes)
      backfill.py:run_backfill() --> ledger_ranges.py:plan_chunks()
          range + node ranges + CHUNK_SIZE + done chunks → (chunks to download, ranges the node does not have)
  Stage 4: backfill · start worker processes   (files: backfill.py, store.py, source.py, fetcher.py)
      backfill.py:run_backfill() --> backfill.py:_run_pool()
          Config + list of chunks → results per chunk; stops cleanly on stop file / signal / low disk
      backfill.py:_run_pool() --> backfill.py:_init_worker()
          once per worker: shared stop Event + log queue + log level
      backfill.py:_run_pool() --> backfill.py:_run_chunk_in_process()
          (Config, chunk) sent to a worker process → ChunkResult
      backfill.py:_run_chunk_in_process() --> store.py:MongoStore.from_config()
          each worker opens its own MongoDB client
      backfill.py:_run_chunk_in_process() --> source.py:WsSource.from_config()
          each worker opens its own websocket client
      backfill.py:_run_chunk_in_process() --> backfill.py:process_chunk()
          source, store, chunk, CONCURRENCY, RetryPolicy, stop check → ChunkResult (ok / failed counts)
      backfill.py:process_chunk() --> fetcher.py:ingest_ledger()
          one ledger number per call (CONCURRENCY at a time) → IngestResult
  Stage 5: Fetch one ledger from the node   (files: fetcher.py, source.py)
      fetcher.py:ingest_ledger() --> source.py:WsSource.get_ledger()
          ledger number → raw ledger answer (dict, API v2, transactions expanded)
      source.py:WsSource.get_ledger() --> source.py:WsSource.request()
          {command: ledger, ledger_index, transactions: true, expand: true} → JSON result
      source.py:WsSource.request() --> source.py:WsSource._get_conn()
          → the open websocket (opens one if needed; only one reconnect at a time)

      source.py:WsSource.request() --> source.py:WsSource._request_on()

  Stage 6: Convert to MongoDB documents   (files: fetcher.py, transform.py)
      fetcher.py:ingest_ledger() --> transform.py:parse_ledger_result()
          ledger number + raw answer → (ledger doc, list of tx docs, list of meta docs); not validated / malformed → error
      transform.py:parse_ledger_result() --> transform.py:build_ledger_doc()
          ledger header fields → ledger document (block_number, hashes, close time ...)
      transform.py:parse_ledger_result() --> transform.py:flatten_transactions()

      transform.py:flatten_transactions() --> transform.py:derived_tx_fields()

  Stage 7: Save to MongoDB   (files: fetcher.py, store.py)
      fetcher.py:ingest_ledger() --> store.py:MongoStore.save_ledger_bundle()

      fetcher.py:ingest_ledger() --> store.py:MongoStore.clear_failure()

  Stage 8: Retry or record the failure   (files: fetcher.py, errors.py, store.py)

  Stage 9: backfill · mark chunks done and report   (files: backfill.py, store.py, cli.py)
