# ARCHITECTURE

## Flow
```
xrpld (local, full history)
  │ ws JSON-RPC api_version 2: `ledger {transactions:true, expand:true}` (ONE request per ledger)
  ▼
WsSource ──▶ ingest_ledger (retry/backoff) ──▶ transform.parse_ledger_result
                                                   │ ledger doc + tx docs + meta/memo docs
                                                   ▼
                                            MongoStore.save_ledger_bundle
                                       (txs → metas → ledger doc LAST, all upserts)
```
Modes:
- **Backfill pipeline:** `prepare_ledger` fetches and transforms; ledgers with >=64 transactions use one dedicated transform thread per process, while smaller ledgers avoid executor overhead (a count heuristic can miss large metadata). A queue of at most `min(CONCURRENCY, 8)` prepared ledgers feeds up to `min(CONCURRENCY, 16)` writers. Writers batch up to 16 ledgers / a soft 2,000-document limit, preserving txs -> metas -> ledger completion ordering. Batches that exhaust retries fall back to per-ledger saves. Stage timings are overlapping wall-time totals, not CPU measurements. Queue/batch limits count records rather than bytes; large responses still require memory headroom. Stops drain prepared work before chunk completion is considered.
- **Shared retry stages:** `prepare_ledger` retries node/validation failures; `persist_bundles` retries database operations using the same prepared data. `ingest_ledger` composes both for live tail, fetch, retries and repair; backfill decouples them through its queue. No raw staging collection or index changes.
- **backfill**: `server_info.complete_ledgers` ∩ requested range → grid-aligned chunks (default 1000 ledgers) → spawn `ProcessPoolExecutor` of N processes, one chunk in flight per process; each runs asyncio with `CONCURRENCY` in-flight ledgers on one ws connection. Finished chunks stored in metadata collection (`backfill_chunk:<s>-<e>`); reruns skip them. A stopped chunk (stop file) ends submission; a dead worker (OOM kill) breaks the pool, backfill stops and counts unfinished chunks as incomplete. Workers set up their own logging (spawn children inherit none). CLI exit codes (all commands): 0 ok, 1 failures/incomplete/verify problems, 2 config/usage error or wrong network, 3 node lacks part of the backfill range, 4 node or MongoDB unreachable/error, 130 Ctrl+C; errors print `error: <Type>: <msg>` without a traceback.
- **tail**: poll `server_info` validated seq, ingest `checkpoint+1..latest`, store checkpoint per ledger (`$max`: it never moves back). No checkpoint ⇒ start after the highest stored ledger (where backfill ended) if it is ≤ `BIG_GAP` (1000) behind; further behind or empty DB ⇒ the node's current ledger, with a WARNING giving the `backfill --start … --end …` command for the hole. A legacy string checkpoint is rewritten as a number once. A ledger that failed all retries advances the checkpoint only if it was recorded in the failed collection; otherwise tail holds the checkpoint, backs off and retries it.
- **retry-failed**: re-ingest ledgers listed in the failed collection, bounded rounds. Failures whose reason is a lost connection (`ConnectionLost`, 1009 / message too big) are retried last, one at a time, so an oversized ledger cannot kill its neighbours again.
- **Stopping**: stop file `current_process=0` or SIGTERM (POSIX; handler in the CLI and in every pool worker) — in-flight work finishes, nothing new starts (`WsSource` also gives up between connect attempts: `StopRequested`, neither retried nor recorded as a ledger failure), stopped chunks stay unmarked, exit code as for the stop file. On Windows use the stop file. `.env` comes from `ENV_FILE`, else `<XRPL_INGEST_HOME or cwd>/.env`, decoded by BOM through `support.files.load_env`; no ancestor-directory search.
- **verify**: gaps in ledger collection, and tx count ≠ `num_transactions`.

## Package layout
- `xrpl_ingest/` — the fetch path: `cli` (commands), `config` (settings + fixed XRPL constants), `errors`, `source` (node websocket), `transform` (node data → docs, lossless), `store` (MongoDB), `fetcher` (one ledger with retries), `backfill`, `tail`, `repair` (verify --repair/--deep, tx), `ledger_ranges`.
- `xrpl_ingest/support/` — helpers around it: `files` (.env/base dir, BOM-safe text, backfill_range.txt), `runcontrol` (stop file, signals, one-instance lock), `monitor` (MIN_FREE_GB, `health`), `doctor` (`doctor`/`config`), `logsetup` (logging, progress/ETA). Nothing in `support/` is on the per-ledger hot path except the stop check and logging.

## Key components
`WsSource` multiplexes requests by id over one socket, reconnects lazily (single lock), fails over across `SERVERS`, rejects servers whose `network_id` ≠ expected (absent ⇒ accepted, WARNING once per process; default 0 = mainnet; all servers wrong ⇒ `NetworkMismatch`, not retried), drops a socket only when nothing at all has arrived on it for `REQUEST_TIMEOUT` (a slow request just times out alone), logs why a socket died (websockets close code) and puts it in the `ConnectionLost` message; credentials in server URLs are redacted everywhere. Backoff (ledger retries and reconnects) is exponential with equal jitter, exponent capped (`MAX_BACKOFF_EXPONENT`). `errors.is_retryable` decides retry: `TransientError`, retryable `RpcError` codes, any `PyMongoError`. Everything else (e.g. `lgrNotFound`, `MalformedLedger`) fails fast into the failed collection.

## Why
- Own node removes rate limits, so the legacy 2-phase (ledger list, then tx) design collapses to 1 request/ledger.
- Ledger doc last + upserts ⇒ crash-safe and idempotent; ledger presence = "tx complete". `verify` cross-checks.
- Chunks on a fixed grid ⇒ resume works regardless of `--start`.

## Constraints
- WSL testing reproduced a broken-pool shutdown deadlock: workers intercept SIGTERM, while the executor manager joins them under its shutdown lock. Hard abort now kills workers before calling non-waiting executor shutdown; normal stop still drains in-flight work. Verified with real Linux worker-death tests and transient systemd ingestion services against a synthetic node and disposable MongoDB.
- Main CLI checks node readiness before ingestion, fetch, tx and verify repair dispatch: synced server state plus a positive, available validated sequence. If a native node's nonempty disk range omits the tip, one direct hash-list request must prove that exact ledger is validated and available, using repair's existing response validator. Clio omits server_state, so that check asks its connected xrpld for state with ledger_index=current while retaining Clio's own coverage check. Unsynced nodes exit 4 with wait/rerun guidance before command work; diagnostic and offline verification paths remain accessible. This startup snapshot does not guarantee historical range coverage or prevent later disconnects.
- Deep repair rechecks hashes for every target after writing, using a set for target membership, and honors stop checks during that comparison. New post-repair mismatches/outages are counted in the summary. Lossless collision comparison distinguishes nested bool/int/float values; only mapped top-level values use the existing integer-string coercion rule.
- Request deadlines cover both WebSocket send and reply. A stalled/cancelled send drops the transport; a reply timeout preserves a connection that received other traffic. Node status objects and validated sequences are checked at the shared source boundary and malformed responses raise retryable node errors.
- Checkpoint parsing is shared by tail/status and health; malformed stored progress raises an actionable configuration error without rewriting it. Doctor only reads lock metadata and makes no assertion about current OS ownership; actual ingestion lock enforcement is unchanged.
- Installer helpers accept BOM-encoded configuration, preserve MongoDB URI-file mode, reserve unique backups and publish a repaired validator file before changing the config pointer. Linux derives the WebSocket URL from the existing managed stanza unless `NODE_WS` overrides it. These paths have isolated fixture checks, not target-host deployment verification.
- Full-history sizing (disk, RAM, NVMe) comes from user-supplied notes, **not verified** against docs; get current numbers before buying hardware.
- Mongo doc mixes types for `Amount`/`TakerGets`/`TakerPays` (int drops vs object) — inherited from legacy schema.
- ws messages for big ledgers are several MB; `MAX_MESSAGE_MB` (default 64) must stay above the largest ledger.
- Real mainnet CLI and transient systemd scenarios passed from WSL through public Clio with real MongoDB (27 CLI-run ledgers / 2,350 transactions). After the direct-tip readiness fix, local CLI (27 ledgers / 2,432 transactions), systemd, installer trial functions and three interruption/recovery scenarios passed on October 25. Sustained local-node stability failed; real throughput profiles remain unmeasured. `tests/test_integration.py` (marker `integration`) separately runs the real spawn pool against a fake websockets node (`tests/fake_xrpld.py`) and a local MongoDB throwaway DB; it skips when MongoDB is absent or `XRPL_INGEST_NO_INTEGRATION=1`.
