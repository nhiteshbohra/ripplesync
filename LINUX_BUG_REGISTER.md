| LNX-001 | High | Explicit Ubuntu/Debian compatibility | [`setup/common.sh`](./setup/common.sh), `check_platform`; [`install.sh`](./install.sh), `step_mongodb` | **Partially addressed.** Installer now gates Ubuntu 20.04/22.04/24.04 and Debian 11/12 on x86_64; Debian requires existing/external MongoDB. Native distro runs are outstanding. |
| LNX-002 | High | Never silently overwrite XRPL configuration | [`setup/edit_cfg.py`](./setup/edit_cfg.py), `_set_managed_stanza`, `_ensure_unique_stanza`, `main`; [`setup/xrpld_check.py`](./setup/xrpld_check.py), `run`; [`install.sh`](./install.sh), `step_node` | **Mitigated.** Conflicting/duplicate managed stanzas and validator config/list replacements fail closed; explicit manual `--overwrite-existing` is available. | LNX-003 | High | Preserve existing MongoDB/package/systemd configuration | [`setup/common.sh`](./setup/common.sh), `install_file_if_absent_or_same`, `install_xrpld_pkg`, `install_mongodb`, `install_ingest_units` | **Mitigated.** Existing differing apt source/key files and units are not overwritten; an existing MongoDB config blocks package installation when `mongod` is absent. Native idempotency/recovery tests are outstanding. |
| LNX-004 | High | Service readiness and controlled restart | [`deploy/systemd/xrpl-tail.service`](./deploy/systemd/xrpl-tail.service), [`deploy/systemd/xrpl-backfill.service`](./deploy/systemd/xrpl-backfill.service) | **Partially addressed.** Readiness runs `doctor --mongo --node`; restart interval and burst limits are set. | LNX-005 | High | Restrictive service account and filesystem/network permissions | [`setup/common.sh`](./setup/common.sh), `install_ingest_units`; both unit files | **Partially addressed.** Root is rejected, a selected existing account is access-checked, `UMask`, capabilities, address families, and filesystem protections are set. The installer does not provision a dedicated account or ACLs; `ProtectHome` is not enabled because state currently resides under the repo. |
| LNX-006 | High | Repeatable install and recovery after partial failure | [`install.sh`](./install.sh), `step_base_packages`, `step_mongodb`, `step_node`, `make_venv`; [`setup/common.sh`](./setup/common.sh) | **Open.** Steps are partly idempotent and config writes have backups/atomic replacement, but there is no transaction journal or automatic rollback for package, ownership, service, or venv changes. |
| LNX-007 | High | Upgrade rollback | [`install.sh`](./install.sh), `make_venv`; [`requirements.txt`](./requirements.txt), [`requirements-lock.txt`](./requirements-lock.txt) | **Open.** The active venv is upgraded in place. The available lock is Windows-specific; no Linux lock or tested rollback environment exists. |
| LNX-008 | High | Firewall, MongoDB authentication, network identity | [`setup/common.sh`](./setup/common.sh), `firewall_note`; [`setup/edit_cfg.py`](./setup/edit_cfg.py), `_validate_local_ws_stanza`; [`xrpl_ingest/cli.py`](./xrpl_ingest/cli.py), doctor commands | **Partially addressed.** Node doctor validates network identity/source health and config preflight refuses a non-loopback admin WebSocket. | LNX-009 | High | Continuous monitoring and supervisor recovery | [`xrpl_ingest/cli.py`](./xrpl_ingest/cli.py), `health`, `status`, `recover-gaps`, `reconcile`; systemd templates | **Partially addressed.** CLI health/recovery exists and systemd restarts process failures. There is no independent monitor/alert service or stalled-worker supervisor test on Linux. |
| LNX-010 | High | Multi-host leases/fencing | [`xrpl_ingest/store.py`](./xrpl_ingest/store.py), recovery-job lease methods; [`xrpl_ingest/recovery.py`](./xrpl_ingest/recovery.py), recovery worker | **Unverified/partial.** Recovery jobs use database leases and fencing.
