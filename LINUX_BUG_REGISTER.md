|---|---|---|---|---|
| LNX-001 | High | Explicit Ubuntu/Debian compatibility | [`setup/common.sh`](./setup/common.sh), `check_platform`; [`install.sh`](./install.sh), `step_mongodb` | **Partially addressed.** Installer now gates Ubuntu 20.04/22.04/24.04 and Debian 11/12 on x86_64; Debian requires existing/external MongoDB. Native distro runs are outstanding. |
| LNX-002 | High | Never silently overwrite XRPL configuration | [`setup/edit_cfg.py`](./setup/edit_cfg.py), `_set_managed_stanza`, `_ensure_unique_stanza`, `main`; [`setup/xrpld_check.py`](./setup/xrpld_check.py), `run`; [`install.sh`](./install.sh), `step_node` | **Mitigated.** Conflicting/duplicate managed stanzas and validator config/list replacements fail closed; explicit manual `--overwrite-existing` is available. Preflight runs before stopping `xrpld` or changing DB ownership. Native config/install test is outstanding. |
| LNX-003 | High | Preserve existing MongoDB/package/systemd configuration | [`setup/common.sh`](./setup/common.sh), `install_file_if_absent_or_same`, `install_xrpld_pkg`, `install_mongodb`, `install_ingest_units` | **Mitigated.** Existing differing apt source/key files and units are not overwritten; an existing MongoDB config blocks package installation when `mongod` is absent. Native idempotency/recovery tests are outstanding. |
| LNX-004 | High | Service readiness and controlled restart | [`deploy/systemd/`](./deploy/systemd), [`setup/common.sh`](./setup/common.sh), [`tests/test_linux_deploy.py`](./tests/test_linux_deploy.py) | **Implemented in templates; source-level tested only.** Dedicated recovery, bounded reconcile, and monitor services/timers are installed; restart/readiness and sandbox assertions pass. Native `systemd-analyze verify`, boot, dependency-loss, restart-limit, and recovery tests are **blocked**. Vendor `mongod`/`xrpld` policies are not changed. |
| LNX-005 | High | Restrictive service account and filesystem/network permissions | [`setup/common.sh`](./setup/common.sh), `install_ingest_units`; both unit files | **Partially addressed.** Root is rejected, a selected existing account is access-checked, `UMask`, capabilities, address families, and filesystem protections are set. The installer does not provision a dedicated account or ACLs; `ProtectHome` is not enabled because state currently resides under the repo. |
| LNX-006 | High | Repeatable install and recovery after partial failure | [`install.sh`](./install.sh), `step_base_packages`, `step_mongodb`, `step_node`, `make_venv`; [`setup/common.sh`](./setup/common.sh) | **Partially addressed.** Python dependencies now build in a candidate venv and preserve the previous environment; other package, ownership, service, and node changes still have no transaction journal or automatic rollback. Native failure/restart tests are **blocked**. |
| LNX-007 | High | Upgrade rollback | [`setup/common.sh`](./setup/common.sh), [`requirements-linux-py312-x86_64.lock`](./requirements-linux-py312-x86_64.lock), [`LINUX_ROLLBACK_GUIDE.md`](./LINUX_ROLLBACK_GUIDE.md) | **Implemented in source; native verification blocked.** CPython 3.12 x86_64 exact versions and wheel hashes are pinned; a candidate is installed with hash checks, consistency-checked, and swapped only when services/timers are inactive. The previous venv is retained. Stub tests and cross-target wheel resolution passed; native install, interrupted swap, and rollback have not run. |
| LNX-008 | High | Firewall, MongoDB authentication, network identity | [`setup/common.sh`](./setup/common.sh), `firewall_note`; [`setup/edit_cfg.py`](./setup/edit_cfg.py), `_validate_local_ws_stanza`; [`xrpl_ingest/cli.py`](./xrpl_ingest/cli.py), doctor commands | **Partially addressed.** Node doctor validates network identity/source health and config preflight refuses a non-loopback admin WebSocket. The installer only prints a peer firewall note and does not enable MongoDB auth or validate the host firewall. |
| LNX-009 | High | Continuous monitoring and supervisor recovery | [`deploy/systemd/xrpl-monitor.service`](./deploy/systemd/xrpl-monitor.service), [`deploy/systemd/xrpl-monitor.timer`](./deploy/systemd/xrpl-monitor.timer), [`setup/monitor_services.sh`](./setup/monitor_services.sh) | **Implemented in source; native verification blocked.** A one-minute timer checks failed tail/backfill/recovery/reconcile units and the CLI tail-health/stalled-checkpoint check. Failures are journal-only; no external alert route is configured. |
| LNX-010 | High | Multi-host leases/fencing | [`xrpl_ingest/store.py`](./xrpl_ingest/store.py), [`xrpl_ingest/recovery.py`](./xrpl_ingest/recovery.py), [`xrpl_ingest/tail.py`](./xrpl_ingest/tail.py) | **Partially implemented and unit tested.** Recovery writes are lease-checked before persistence; job completion requires full-range node verification evidence. Tail claims a database singleton lease; writes are checked and checkpoint updates are monotonic. The lease check/write pair is not atomic, so a paused worker may finish an in-flight write after takeover; native multi-host tests are **blocked**. Backfill is not globally single-owner. |
| LNX-011 | Critical | Zero unexplained missing ledgers and transaction mismatches | [`xrpl_ingest/repair.py`](./xrpl_ingest/repair.py), [`xrpl_ingest/recovery.py`](./xrpl_ingest/recovery.py), [`xrpl_ingest/store.py`](./xrpl_ingest/store.py) | **Partially implemented; data qualification unverified.** Bounded reconciliation persists checked/uncovered intervals and cannot mark an uncovered range verified. Recovery success is lease-bound and requires full-range deep node checks. No bounded real-mainnet native Linux reconciliation or full-history evidence exists. |
| LNX-012 | High | Reboot, SIGTERM, SIGKILL, source/Mongo restart recovery | [`deploy/systemd/`](./deploy/systemd), [`xrpl_ingest/support/runcontrol.py`](./xrpl_ingest/support/runcontrol.py), recovery/fetch paths | **Blocked on native Linux.** Unit templates and interruption code have source-level coverage only. No current-commit Ubuntu reboot, SIGTERM/SIGKILL, source restart, or Mongo restart test has run. WSL evidence is not substituted. |
| LNX-013 | High | 24-hour and 72-hour endurance evidence | [`tests/reliability_soak.py`](./tests/reliability_soak.py) | **Blocked.** The harness can collect evidence, but a dedicated native Linux environment and 24-hour/72-hour runs are unavailable. |
| LNX-014 | Medium | MongoDB signing-key verification | [`setup/common.sh`](./setup/common.sh), `install_mongodb` | **Open.** The fingerprint is displayed but not pinned to an independently published expected value. Existing differing key material is preserved, but first-use trust remains. |
| LNX-015 | High | Atomic stale-worker write fencing | [`xrpl_ingest/recovery.py`](./xrpl_ingest/recovery.py), [`xrpl_ingest/tail.py`](./xrpl_ingest/tail.py), [`xrpl_ingest/store.py`](./xrpl_ingest/store.py) | **Partially addressed; residual race remains.** Each new write checks the current lease, and completion/checkpoint updates are fenced or monotonic. MongoDB does not atomically couple the lease check to all multi-collection ledger writes; an already-started write can cross lease takeover. Do not claim strict stale-worker exclusion or multi-host production safety until redesigned/qualified on the supported Mongo topology. |

No critical finding is marked fixed. See [`LINUX_TEST_RESULTS.md`](./LINUX_TEST_RESULTS.md) for what actually ran and [`LINUX_IMPLEMENTATION_PLAN.md`](./LINUX_IMPLEMENTATION_PLAN.md) for closure gates.
